# Comic Gen 첫 버전 명세: IT 교육용 에셋 조합 만화

Status: ready-for-agent

## Problem Statement

IT 개념을 교육할 때 등장인물의 대화와 물건 전달로 설명하면 이해하기 쉽지만, 매번 만화를 직접 그리거나 인물과 말풍선을 배치하는 작업이 오래 걸린다. 작성자는 귀엽고 단순한 캐릭터를 반복 사용하며, PlantUML처럼 짧은 코드로 교육 만화를 만들고 문서에 쉽게 삽입하고 싶다.

각 인물은 웹 서버, 데이터베이스, 클라이언트 등 어떤 개념인지 알아볼 수 있어야 한다. 표정, 손 제스처, 대사, 대화 상대, 들고 있는 물건과 건네주는 물건을 표현하면 첫 버전의 주요 교육 장면을 구성할 수 있다.

## Solution

미리 준비한 에셋 라이브러리를 선언적인 만화 코드로 선택하고 조합하는 브라우저 렌더러를 제공한다. 캐릭터와 대화를 적으면 컷, 인물과 말풍선을 자동 배치하고, 필요하면 배치를 조정한다. 결과는 SVG로 표시·저장하고 PNG 이미지로도 내보낸다. 렌더링과 이미지 내보내기는 클라이언트에서 처리한다.

캐릭터는 귀엽고 간단하게 표현하되 역할에 맞춘 몸체를 사용한다. 예를 들어 DB는 원통, 웹 서버는 상자 형태로 구분하고 이름표로 보완한다. 손은 기본으로 생략하고 제스처, 소품 들기와 전달에 필요할 때만 작은 형태로 표시한다. 한 컷의 대표 지원 장면은 두세 캐릭터가 서로 대화하는 모습이다.

같은 에셋과 렌더링 결과를 재사용하도록 클라이언트 캐시를 둔다. 문서 도구는 동일한 렌더러를 연결해 코드 블록을 만화로 표시할 수 있게 한다. 특정 서비스의 실제 연동 완료를 이 명세의 전제로 삼지 않는다.

## User Stories

1. 교육 콘텐츠 작성자로서, 짧은 코드로 만화를 작성하고 싶다. 그림을 직접 그리는 대신 설명할 내용에 집중할 수 있기 때문이다.
2. 교육 콘텐츠 작성자로서, 준비한 에셋에서 캐릭터를 선택하고 싶다. 새 그림을 만들지 않고 시작할 수 있기 때문이다.
3. 교육 콘텐츠 작성자로서, 같은 캐릭터를 여러 컷과 만화에서 재사용하고 싶다. 설명의 일관성을 유지하고 작성 시간을 줄일 수 있기 때문이다.
4. 학습자로서, 캐릭터의 몸체와 이름표로 역할을 구분하고 싶다. 누가 웹 서버이고 누가 데이터베이스인지 알 수 있기 때문이다.
5. 교육 콘텐츠 작성자로서, 한 컷에 두세 캐릭터를 넣고 싶다. 여러 개념의 상호작용을 표현할 수 있기 때문이다.
6. 교육 콘텐츠 작성자로서, 캐릭터 표정을 선택하고 싶다. 질문, 이해, 혼란과 같은 반응을 보여줄 수 있기 때문이다.
7. 교육 콘텐츠 작성자로서, 표정을 생략했을 때 자연스러운 기본 표정을 얻고 싶다. 매번 모든 옵션을 작성할 필요가 없기 때문이다.
8. 교육 콘텐츠 작성자로서, 손 제스처를 선택하고 싶다. 가리키거나 강조하는 행동을 표현할 수 있기 때문이다.
9. 교육 콘텐츠 작성자로서, 제스처가 필요 없는 캐릭터의 손은 생략하고 싶다. 그림이 단순하고 읽기 쉬워지기 때문이다.
10. 교육 콘텐츠 작성자로서, 대사의 화자를 지정하고 싶다. 말풍선이 누가 말하는지 정확히 보여줄 수 있기 때문이다.
11. 교육 콘텐츠 작성자로서, 대화 상대를 지정하고 싶다. 세 캐릭터가 있어도 누구에게 하는 말인지 구분할 수 있기 때문이다.
12. 교육 콘텐츠 작성자로서, 한국어와 영어 대사를 쓰고 싶다. 실제 IT 교육 자료에 사용할 수 있기 때문이다.
13. 학습자로서, 말풍선을 자연스러운 순서로 읽고 싶다. 대사의 순서를 헷갈리지 않고 내용을 이해할 수 있기 때문이다.
14. 교육 콘텐츠 작성자로서, 캐릭터가 소품을 들고 있는 모습을 표현하고 싶다. 요청, 데이터와 결과 등의 개념을 물건으로 보여줄 수 있기 때문이다.
15. 교육 콘텐츠 작성자로서, 한 캐릭터가 다른 캐릭터에게 소품을 건네는 모습을 표현하고 싶다. 전달 관계를 설명할 수 있기 때문이다.
16. 교육 콘텐츠 작성자로서, 제공되지 않은 캐릭터나 표정을 참조하면 위치를 알 수 있는 오류를 받고 싶다. 코드를 빠르게 수정할 수 있기 때문이다.
17. 교육 콘텐츠 작성자로서, 화자나 상대가 존재하지 않는 대사를 확인하고 싶다. 잘못된 장면이 조용히 그려지는 일을 피할 수 있기 때문이다.
18. 교육 콘텐츠 작성자로서, 인물과 말풍선이 자동 배치되길 원한다. 좌표를 일일이 지정하지 않고 만화를 만들 수 있기 때문이다.
19. 교육 콘텐츠 작성자로서, 자동 배치가 의도와 다르면 조정하고 싶다. 중요한 교육 장면의 구도를 직접 통제할 수 있기 때문이다.
20. 교육 콘텐츠 작성자로서, 코드를 수정하면 미리보기를 갱신하고 싶다. 편집 결과를 바로 확인할 수 있기 때문이다.
21. 교육 콘텐츠 작성자로서, SVG를 저장하고 싶다. 크기를 바꾸거나 문서에 삽입해 사용할 수 있기 때문이다.
22. 교육 콘텐츠 작성자로서, PNG를 저장하고 싶다. SVG를 지원하지 않는 문서나 발표 자료에도 사용할 수 있기 때문이다.
23. 교육 콘텐츠 작성자로서, 같은 만화를 다시 표시할 때 캐시된 결과를 사용하고 싶다. 불필요한 렌더링을 줄일 수 있기 때문이다.
24. 교육 콘텐츠 작성자로서, 대사나 에셋을 수정하면 최신 결과를 보고 싶다. 캐시 때문에 오래된 설명이 표시되지 않아야 하기 때문이다.
25. 교육 콘텐츠 작성자로서, 여러 컷 중 한 컷을 수정할 때 나머지 결과를 재사용하고 싶다. 편집 중 응답성을 유지할 수 있기 때문이다.
26. 문서 도구 통합자로서, 만화 코드 블록을 브라우저 렌더러에 전달하고 싶다. 글 사이에 교육 만화를 표시할 수 있기 때문이다.
27. 문서 도구 통합자로서, 렌더링 서버 없이 정적 에셋과 렌더러를 배포하고 싶다. 서비스 운영과 도입 부담을 줄일 수 있기 때문이다.
28. 교육 콘텐츠 작성자로서, 기기의 기본 이모지 그림에 의존하지 않는 캐릭터를 사용하고 싶다. 플랫폼에 따라 캐릭터 모습이 달라지는 일을 줄일 수 있기 때문이다.

## Implementation Decisions

### 합의한 제품 방향

- 첫 버전은 준비한 에셋을 참조하고 조합한다. 코드에서 새 그림을 직접 정의하는 기능은 제외한다. 사용자가 에셋 제작 도구나 임의 SVG 업로드까지 요청한 것으로 확대하지 않는다.
- 필요한 작성 정보는 캐릭터 에셋과 장면 내 식별자, 표정, 손 제스처, 대사, 대화 상대, 소품, 소품을 들거나 건네는 관계다. 에셋의 이름과 같은 에셋을 사용하는 복수 등장인물의 식별자를 구분한다.
- 대사의 화자와 대화 상대는 서로 다른 관계다. 말풍선 꼬리는 화자를 가리키고, 대화 상대는 시선·방향 또는 관계 표현에 사용한다. 전달 소품에는 주는 인물과 받는 인물을 구분한다.
- 손 제스처와 소품 표현은 정적인 컷 표현이다. 전달 애니메이션이나 물리 시뮬레이션을 요구하지 않는다.
- 귀여운 단순 캐릭터를 사용하되 역할별 몸체와 이름표로 정체성을 표현한다. 초기 동그란 몸 시각 초안은 탐색 자료이며 역할별 몸체의 최종 에셋이 아니다.
- 좌표 없는 기본 사용에서 두세 인물과 말풍선이 서로 구분되도록 자동 배치한다. 컷 내부에 수용하기 어려운 대사는 자동 줄바꿈과 배치 조정으로 처리하고, 처리 불가능한 경우 작성자가 수정할 수 있는 진단을 제공한다.
- 브라우저에서 렌더링과 내보내기를 처리한다. 에셋·렌더러의 정적 호스팅과 렌더링 계산 서버는 구분한다. 브라우저 렌더링만으로 모든 문서 서비스에서 자동 지원되는 것은 아니며 문서 통합 연결부가 필요하다.
- 클라이언트에 에셋과 렌더링 결과 캐시를 둔다. 내용이 바뀌었을 때 오래된 결과를 반환하지 않는 것을 핵심 동작으로 삼는다.

### 명세를 구체화하기 위한 구현 제안

다음 항목은 사용자에게 실제 코드를 보여주거나 구현으로 검증한 결정이 아닌 초기 구현 제안이다. 명세의 사용자 관찰 동작을 유지하는 한 구현 담당자가 구체화할 수 있다.

- 하나의 공개 렌더링 경계를 둔다. 선언적인 만화 코드, 에셋 라이브러리와 출력 옵션을 입력받아 SVG와 작성자가 이해할 수 있는 진단을 반환한다. 파서, 참조 검증, 에셋 합성, 자동 배치는 이 경계 안에 둔다.
- 동일한 SVG를 브라우저 미리보기와 SVG 다운로드에 사용하고, PNG 내보내기는 그 결과를 래스터 이미지로 변환한다. 기본 캐릭터와 소품은 SVG 에셋으로 준비한다.
- 작성자가 컷과 대사 순서를 명시하고 엔진이 그 안의 기본 배치를 계산하는 흐름부터 검증한다. 이야기만으로 컷 수를 추론하는 기능은 확정된 요구가 아니다.
- 캐시 키에 정규화한 장면 내용, 참조 에셋 버전, 렌더러·배치 정책 버전, 글꼴과 출력 옵션을 포함한다. 에셋과 컷 결과를 나눠 재사용한다. 메모리 캐시부터 시작하고 영속 저장의 필요성은 측정 후 판단한다.
- 캐시에 크기 한도를 두고 오래 사용하지 않은 항목을 제거한다. 내보낼 PNG는 크기 옵션이 동일할 때만 재사용한다.
- 초기에는 함께 제공한 신뢰할 수 있는 정적 에셋을 사용하고, 에셋 로딩과 글꼴 준비가 끝난 뒤 화면과 내보내기 결과를 확정한다. 글꼴 조건이 달라지면 해당 캐시를 갱신한다.
- 입력은 선언 데이터로 해석한다. 대사는 SVG 마크업이나 실행 가능한 코드로 해석하지 않고 텍스트로 표시한다. 같은 문서에서 여러 만화를 표시할 때 SVG 내부 식별자 충돌을 피한다.
- 특정 문서 서비스에 종속되지 않는 연결부를 제공한다. 실제 코드 블록 구분자, 패키지 형식과 slog.gg 연동 방법은 아직 검증하지 않았다.

## Testing Decisions

- 가장 높은 검증 경계는 브라우저에서 만화 코드를 입력하고 미리보기 및 SVG·PNG 내보내기 결과를 관찰하는 공개 흐름이다. 내부 함수 분해나 캐시 구현 방식 자체를 테스트의 계약으로 삼지 않는다.
- 이 검증 경계는 제안이며, 명세 전달 시 사용자에게 기대와 일치하는지 확인한다.
- 대표 장면은 웹 서버와 DB의 대화, 클라이언트·웹 서버·DB의 세 인물 대화, 인물이 소품을 들고 있는 장면, 특정 상대에게 소품을 건네는 장면이다. 특정 교육 주제의 채택과는 별개인 검증 예제다.
- 대표 장면에서 몸체의 역할 구분, 표정 선택, 손 생략·표시, 화자와 상대, 소품의 주체를 확인한다. 글자 내용과 읽기 순서를 검증하고 의미 없는 SVG 문자열 전체 비교에 의존하지 않는다.
- 좌표를 지정하지 않은 두세 인물의 겹침, 말풍선 잘림, 긴 한국어·영어 대사와 혼합 대사, 대사에 포함한 특수문자의 표시를 브라우저 결과에서 확인한다.
- SVG와 PNG가 같은 장면을 표현하고 선택한 출력 크기를 따르는지 확인한다. 글꼴과 테스트 환경을 고정한 대표 그림만 제한적으로 시각 비교한다.
- 존재하지 않는 에셋·표정·화자·상대·전달 대상이 작성자가 수정할 수 있는 진단을 반환하는지 확인한다.
- 같은 입력은 결과가 동일하고 캐시 재사용이 가능해야 한다. 대사, 표정, 에셋 버전, 글꼴 또는 출력 크기를 변경하면 갱신된 결과가 나오는지 검증한다. 변경하지 않은 다른 컷의 재사용도 구현 후 성능 관찰로 확인한다.
- 같은 페이지의 복수 만화가 서로의 SVG 요소나 상태에 영향을 주지 않는지 확인한다.
- 현재 프로젝트에는 제품 구현과 기존 테스트가 없다. 따라서 기존 테스트 관행이나 성능 수치가 있는 것으로 가정하지 않는다. 처리 시간과 캐시 적중 효과는 구현 후 대표 장면으로 측정하며 지금 임의의 목표 수치를 약속하지 않는다.

## Out of Scope

- 코드 안에서 도형이나 새 캐릭터 그림을 직접 정의하는 기능.
- 에셋 제작·업로드·온라인 공유·마켓플레이스·동기화 시스템.
- AI 이미지 생성, 완성 웹툰 자동 생성, 이야기에서 장면을 추론하는 기능.
- 복잡한 인체 리깅, 연속 애니메이션과 물리 시뮬레이션.
- 렌더링 계산용 서버와 계정·협업 백엔드.
- CLI, 서버 렌더러, PDF 내보내기와 출판용 인쇄 기능.
- 모든 문서 플랫폼에 대한 첫 버전 동시 연동과 검증하지 않은 slog.gg 연동 완료 주장.
- 기기 기본 이모지 글리프를 주 캐릭터 에셋으로 사용하는 방식.
- 이번 명세 작성 과정에서 제품을 구현하거나 배포하는 작업.

## Further Notes

이 명세는 대화에서 합의한 요구사항을 종합한 것이다. 최종 텍스트 문법, 준비할 에셋 목록·표정·제스처 목록, 수동 배치 옵션, 글꼴 배포와 실제 문서 통합 방식은 아직 프로토타입으로 검증하지 않았다. 이를 합의 완료된 상세 설계로 해석하지 않고 구현 초안과 대표 장면으로 확인한다.

ComicForge는 SVG 합성, 에셋 변형과 말풍선 배치를 참고할 자료다. 브라우저 전용 렌더링이나 인물 자동 배치를 그대로 제공하는 구현으로 가정하지 않는다. 조사에서 명시적인 라이선스가 확인되지 않았으므로 원본 코드와 그림을 복사하는 대신 구조를 참고해 독립적인 구현과 에셋을 준비하는 것을 기본으로 한다.

라이선스·브라우저 동작 등의 판단은 이후 실제 채택 시 다시 검증한다. 캐릭터 제작을 완료했거나 엔진이 동작한다고 주장하는 문서가 아니다.
