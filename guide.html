Comic Gen은 준비된 SVG 에셋을 YAML로 조합하는 브라우저 렌더러입니다. 사람과 IT 캐릭터에 이름표·표정·대사를 더해 교육 자료, 기술 문서와 짧은 이야기를 만듭니다. 그림을 새로 생성하는 AI는 사용하지 않습니다.

빠른 시작문법과 기본값사람·페르소나표정·손·소품배치SDK·저장선택형 뷰어문서 삽입오류 해결

1. 두 캐릭터의 대화 만들기

플레이그라운드에서 이 예제 열기 → 

제목: 요청과 응답
등장인물:
  web: { 그림: 서버, 이름표: 웹 서버 }
  db: { 그림: 데이터베이스, 이름표: DB }
컷:
  - 인물: [ web, db ]
    대사:
      - { 화자: web, 상대: db, 내용: "데이터를 부탁해!" }
      - { 화자: db, 상대: web, 내용: "좋아, 바로 찾아볼게!" }

등장인물은 인물 사전, 컷은 컷 목록입니다. 각 컷의 인물에 등장하는 인물을 적고 대사에 순서대로 대사를 넣으세요. YAML은 들여쓰기를 쓰므로 탭 대신 공백 두 칸을 권장합니다. 콜론·따옴표가 든 대사는 따옴표로 감싸거나 아래의 여러 줄 문법을 사용하세요.

대사 가로위치 / 세로위치 / 글자크기 가로위치/세로위치: 0~1, 기본 자동. 글자크기: 12~32, 기본 18.
전달 주는인물 / 받는인물 / 소품 모두 필수. 서로 다른 인물 ID와 요청, 데이터, 열쇠 중 소품.

사람·외형·페르소나

v0.6.0의 그림: 사람은 준비된 머리·얼굴·옷을 조합합니다. 외형은 피부·머리·옷·안경의 시각적 특징이고, 페르소나는 직무·성격·말투를 유지하며 대사를 작성하는 참고 정보입니다. 인물의 외형과 페르소나는 모든 컷에서 공유합니다. 같은 ID를 참조하고 표정·손·소품만 바꾸세요. 직무·성격을 적어도 대사와 표정은 자동 생성되지 않습니다. 

페르소나:
  분석가: { 직무: 빅데이터 전문가, 성격: 차분하게 근거를 확인한다, 말투: 짧은 질문으로 설명한다 }
등장인물:
  김대리:
    그림: 사람
    이름표: 김대리
    페르소나: 분석가
    외형: { 옷: 재킷, 옷색: "#5379a7", 안경: true }
컷:
  - 인물: [김대리]
    대사: [{ 화자: 김대리, 내용: "클릭과 구매 전환을 나눠서 보죠." }]

최상위 페르소나 사전의 ID를 참조하거나 인물 안에 페르소나: {직무: 마케팅 팀장, 말투: 결론부터 질문한다}처럼 직접 적습니다. 프로필은 직무(1~100자), 성격·말투(각 1~300자) 중 하나 이상이 필요합니다. 프로필은 이름표·외형을 포함하지 않으며 상속·외부 파일 참조는 지원하지 않습니다.

외형 항목 허용 값과 기본값
피부색 #RGB 또는 #RRGGBB. 기본 "#f0c8a6".
머리모양 짧은머리(기본), 단발, 긴머리, 민머리.
머리색 같은 색상 형식. 기본 "#47362f".
옷 셔츠(기본), 재킷, 후드.
옷색 같은 색상 형식. 기본 "#647bd6".
안경 boolean true 또는 false(기본).

외형은 사람에만 지정합니다. 생략한 항목은 기본값을 적용하고 색상은 YAML 주석으로 읽히지 않도록 따옴표로 감쌉니다. 여러 이야기에서도 같은 사람을 쓰려면 등장인물과 페르소나 선언을 함께 재사용하세요. JavaScript에서는 공유 cast·personas 객체와 이야기별 panels를 JSON.stringify({title, cast, personas, panels})로 조합해 기존 SDK에 전달합니다.

3. 표정·손·소품과 전달

v0.7.2부터 사람의 가리키는손은 옷색 팔·손바닥·손가락을 연결해 그립니다.

v0.7.3부터 도형 캐릭터도 흰색 손바닥·엄지·두께 있는 손가락을 연결해 그립니다. 인사손은 펼친 손, 가리키는손은 왼쪽으로 뻗은 손가락으로 구분합니다. 단순한 그림체와 기존 문법·동작 방향은 유지합니다.

v0.7.5의 도형 인사손은 네 손가락을 고른 높이로 펼치고 엄지를 벌립니다. 손목을 기울인 선명한 손바닥과 각도를 크게 벌린 두 잔상, 휘어진 이동선으로 흔드는 인사를 표현하며, SVG·PNG에도 같은 정적인 모습으로 저장됩니다. 

인물:
  - { 식별자: web, 표정: 기쁨, 손모양: 인사손, 든소품: 요청 }
  - { 식별자: db, 표정: 어리둥절 }
전달:
  - { 주는인물: db, 받는인물: web, 소품: 데이터 }

든소품은 인물이 들고 있는 물건, 전달은 인물 사이의 정적인 전달 표현입니다. 전달의 두 끝은 인물 근처에 붙습니다. 애니메이션이나 실제 네트워크 동작은 없습니다. 손 제스처와 든소품을 생략하면 사람은 기본 손을 그리고 기존 아이콘은 손을 그리지 않습니다. 전달을 쓰면 전달용 손이 표시됩니다. 이름표를 바꿔 서버를 선생님에 비유할 수도 있습니다.

손모양: 인사손과 손모양: 가리키는손은 고정된 SVG 그림입니다. 두 손모양은 캐릭터 왼쪽에 표시되고 가리키는손은 왼쪽을 가리킵니다. 대화 상대의 위치에 따라 방향이 바뀌거나 움직이지 않습니다.

4. 여러 컷과 수동 배치

같은 ID를 다음 컷의 인물에도 넣으면 이름표와 에셋을 재사용합니다. 표정·손·소품·좌표는 각 컷에서 지정합니다. 인물 가로위치는 내부 여백을 제외한 가로 영역의 비율, 세로위치는 컷 높이의 비율입니다. 안전한 영역으로 제한되므로 입력한 비율과 최종 위치가 다를 수 있습니다. 대사 가로위치는 말풍선 중심, 세로위치는 상단의 비율입니다. 배율은 좁은 폭에 맞춘 기본 크기에 대한 배율입니다. 

인물:
  - { 식별자: web, 가로위치: 0.25, 세로위치: 0.85, 배율: 0.8 }
  - { 식별자: db, 가로위치: 0.75 }
대사:
  - { 화자: web, 상대: db, 내용: "조금 작게 말할게!", 가로위치: 0.35, 글자크기: 16 }

인물끼리 겹치면 오류를 표시합니다. 수동 말풍선끼리의 겹침이나 전달 선이 다른 인물을 지나는 경우를 모두 자동 회피하지는 않습니다. 자동 배치부터 시작한 뒤 조금씩 조절하세요.

여러 줄 대사

대사:
  - 화자: web
    상대: db
    내용: |-
      첫 번째 줄이에요.
      두 번째 줄은 직접 나눴어요.

긴 대사는 브라우저 글꼴의 실제 폭을 측정해 자동 줄바꿈합니다. 한국어·영어 예제는 여기서 수정할 수 있습니다. 자동 번역 기능은 없습니다.

변화만 적는 네 컷

구성: 이전은 이전 컷의 인물 상태만 상속합니다. ID별로 지정한 설정을 덮어쓰고, 선택 필드의 null은 기본값으로 초기화합니다. 대사와 전달, 다이어그램은 상속하지 않고 각 컷에 새로 적습니다. 첫 컷은 완전히 정의하세요. 

등장인물:
  web: { 그림: 서버, 이름표: 웹 서버 }
  db: { 그림: 데이터베이스, 이름표: DB }
컷:
  - 인물: [ { 식별자: web, 표정: 어리둥절 }, db ]
    대사: [ { 화자: web, 상대: db, 내용: "데이터가 있니?" } ]
  - 구성: 이전
    인물: [ { 식별자: db, 표정: 기쁨, 든소품: 데이터 } ]
    대사: [ { 화자: db, 상대: web, 내용: "찾았어!" } ]
  - 구성: 이전
    인물: [ { 식별자: db, 든소품: null }, { 식별자: web, 표정: 기쁨 } ]
    전달: [ { 주는인물: db, 받는인물: web, 소품: 데이터 } ]
  - 구성: 이전
    인물: [ { 식별자: web, 든소품: 데이터, 손모양: 인사손 } ]
    대사: [ { 화자: web, 상대: db, 내용: "다음에도 함께하자!" } ]

네 컷 예제 수정 →

  • 인물 생략: 이전 인물의 순서·표정·손·든소품·좌표·배율 유지.
  • 기존 ID는 부분 변경, 새 ID는 목록 뒤에 추가. ID 중복은 오류.
  • 손모양/든소품/가로위치/세로위치/배율/표정의 null은 제거 후 기본값 적용.
  • 제외인물: [db]로 이전 인물 제거. 없는 ID는 오류.
  • 인물: []는 전체 비우기이므로 최소 1명 조건 오류. 변경이 없으면 생략.
  • 대사/전달은 생략 또는 []이면 없음. 제공한 목록으로 대체.
  • 등장인물·에셋·이름표는 전체 공유. 배경은 지원하지 않음.
  • 구성: 전체 또는 구성 생략은 전체 정의. 첫 컷의 구성: 이전은 오류.

스마트폰용 컷별 SVG

플레이그라운드는 컷마다 독립 SVG를 세로로 나열합니다. 컷비율의 모바일은 기본 대비 실제 SVG 높이가 2배이며 PNG에도 같은 비율을 적용합니다. 캐릭터와 말풍선을 찌그러뜨리지 않고 내용 주변의 상하 여백을 늘립니다. 가로위치/세로위치는 중앙의 기본 내용 영역을 기준으로 합니다. 명시한 너비는 유지하며 전체 컷 높이를 직접 지정하는 옵션은 없습니다. 다이어그램의 높이는 칠판 영역만 조절합니다. 플레이그라운드에서 기본 비율을 선택할 수 있습니다.

컷 안의 칠판에 Mermaid 다이어그램 넣기

인물과 대사가 같은 컷 안의 다이어그램을 설명하도록 만들 수 있습니다. 다이어그램은 인물·말풍선과 구분되는 칠판 영역을 만듭니다. 종류: 머메이드와 원문은 필수이며, 제목의 기본값은 다이어그램입니다. 선택 항목인 높이는 칠판 높이 160~1200px입니다. 생략하면 그림의 비율에 맞춰 정합니다. 다이어그램은 이전 컷에서 상속하지 않습니다. 

제목: 요청의 순서
등장인물:
  안내자: { 그림: 서버, 이름표: 안내자 }
컷:
  - 인물: [안내자]
    대사: [{ 화자: 안내자, 내용: "요청을 받으면 응답을 돌려줘요." }]
    다이어그램:
      종류: 머메이드
      제목: 요청에서 응답까지
      높이: 300
      원문: |
        sequenceDiagram
          participant 방문자
          participant 서버
          방문자->>서버: 데이터 요청
          서버-->>방문자: 응답

원문은 Mermaid 문법 그대로입니다. 첫 줄에서 classDiagram, sequenceDiagram, flowchart 같은 종류를 고르세요. Mermaid의 명령·식별자·라벨은 한글 문법으로 변환하지 않습니다. 클래스 예제와 시퀀스 예제로 시작할 수 있습니다. 큰 그림은 높이를 늘리거나 여러 컷으로 나누세요.

다이어그램이 있으면 await 컷그리기비동기(source) 또는 await 만화그리기비동기(source)를 사용하세요. 기존 동기 함수의 반환 방식은 그대로이며 다이어그램 입력에는 비동기 함수 사용 안내를 반환합니다. 처음 그릴 때만 Mermaid 11.17.2를 고정 CDN에서 불러오므로 해당 CDN에 연결할 수 있어야 합니다. 전체·개별 컷 SVG와 PNG에 다이어그램도 포함됩니다.

원문은 최대 20,000자입니다. 링크·외부 이미지·HTML·사용자 CSS·노드/간선 메타데이터(@{})·테마/init 설정·frontmatter는 지원하지 않습니다. 구조와 텍스트 라벨을 작성하세요. 출력은 내부 참조만 사용하는 SVG입니다.

5. 브라우저 SDK와 SVG·PNG 저장

최신 주소는 main 브랜치를 따르며 CDN 캐시로 반영이 지연될 수 있습니다. 한글 문법은 v0.3.0부터 지원합니다. 재현 가능한 문서에는 v0.7.5 고정 SDK를 사용하세요. v0.2.1 고정 SDK는 영어 문법 전용입니다. 

import { 컷그리기비동기, exportPng, downloadBlob }
  from 'https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.7.5/cdn/comic-gen.render.js';
await document.fonts.ready;
const result = await 컷그리기비동기(source, {너비: 720, 컷비율: '모바일'});
if (result.diagnostics.length) {
  console.error(result.diagnostics);
} else {
  document.querySelector('#preview').innerHTML = result.panels.map(panel => panel.svg).join('');
  const first = result.panels[0];
  downloadBlob(new Blob([first.svg], {type: 'image/svg+xml'}), 'panel-1.svg');
  const png = await exportPng(first, 2);
  downloadBlob(png, 'panel-1.png');
}

브라우저에서 module 스크립트로 실행하세요. source는 YAML 문자열이며 #preview는 결과를 넣을 요소입니다. 다운로드는 사용자가 버튼을 누르는 이벤트에서 호출하는 것을 권장합니다. 너비는 480~2400, 글꼴과 글꼴버전도 지정할 수 있습니다. 독립 캐시가 필요하면 렌더러만들기(maxCacheBytes)를 사용하고 clearCache()로 비웁니다. 기본 메모리 캐시는 2MB이며 영구 저장되지 않습니다.

완성한 결과에 뷰어 붙이기

렌더링만 사용할 수도 있고, 완성한 결과에 공용 카드·뷰어를 붙일 수도 있습니다. 렌더링 파일은 뷰어를 설치하지 않고, 뷰어 파일은 렌더러를 불러오지 않습니다. 기존 comic-gen.js에는 문서 삽입을 포함한 API가 그대로 있습니다.

필요한 기능 파일
렌더링·SVG·PNG 저장 comic-gen.render.js
완성한 결과에 카드·뷰어 추가 comic-gen.viewer.js
기존 문서·코드 블록 삽입 comic-gen.js 
import { renderPanelsAsync } from
  'https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.7.5/cdn/comic-gen.render.js';
import { mountComicCard } from
  'https://cdn.jsdelivr.net/gh/jhs512/comic-gen@v0.7.5/cdn/comic-gen.viewer.js';
const result = await renderPanelsAsync(source, {panelFormat: 'compact'});
if (result.diagnostics.length) throw new Error(result.diagnostics.join('\n'));
const cleanup = mountComicCard(document.querySelector('#comic-card'), result);
// 내용을 교체하거나 컴포넌트를 제거할 때 cleanup()을 호출합니다.

페이지에 <div id="comic-card"></div>를 준비하세요. Mermaid가 있으면 비동기 렌더링을 마친 결과를 그대로 전달합니다. 카드를 클릭하거나 키보드로 열면 전용 화면에서 읽습니다. 스타일은 사용 시 함께 설치됩니다. TypeScript 선언은 각 파일과 같은 이름의 .d.ts 파일로 제공합니다.

자체 버튼에 연결하려면 createComicViewer()의 open(result, {trigger})를 호출하세요. isOpen으로 상태를 확인하고 close()로 닫습니다. 컴포넌트를 제거할 때 destroy()를 호출하면 이벤트·Blob 이미지· 대화상자와 스크롤 잠금을 정리합니다. 분리 모듈 예제 보기 →

6. 문서·Markdown·CodePen에 삽입하기

컷그리기는 result.panels 배열에 index(0부터), svg, width, height, diagnostics, cache를 반환합니다. 실패하면 최상위 diagnostics와 빈 panels를 반환합니다. 렌더러만들기의 반환 객체에도 renderPanels 메서드가 있습니다. 컷그리기의 컷비율 기본값은 모바일이며 기본으로 바꿀 수 있습니다. 만화그리기와 renderer.render는 전체 통합 SVG를 만들며 컷비율 기본값은 기본입니다. 반환값의 이름과 exportPng/downloadBlob 같은 저장 함수 이름은 번역하지 않습니다.

Markdown의 comic-gen 코드 블록을 pre > code.language-comic-gen으로 변환하면 렌더링합니다. 코드블록그리기비동기(root)는 원하는 컨테이너만 처리할 수도 있습니다. 제목과 첫 컷 썸네일의 카드를 열면 전체 만화를 전용 뷰어에서 읽습니다. 원문은 숨기고 오류는 해당 블록에 표시합니다. 카드·뷰어 스타일은 SDK에 포함됩니다. 다시 호출하면 카드와 열린 뷰어가 갱신됩니다. slog.gg의 $$ 문법은 해당 서비스 파서에 별도 연결해야 합니다.

뷰어는 원래 컷 순서와 내부 좌표를 유지합니다. PC에서는 넓게 열리고 모바일에서는 화면 너비에 맞춥니다. 화면 넘침 방지 체크박스와 100%·150%·200% 보기 크기를 제공합니다. 넘침 방지는 제목·여백을 포함한 가장 큰 한 컷을 가로·세로 화면에 맞춥니다. 전체 만화는 원래 배치로 스크롤해서 읽고, 넘침 방지를 끄면 선택한 보기 크기로 확대합니다. 체크를 바꾸어도 보기 크기는 유지됩니다. 컷 왼쪽은 이전, 오른쪽은 다음 컷이며 버튼과 읽기 영역의 ←/→ 키로도 이동합니다. 현재/전체 컷 수는 실제 1~30컷을 표시합니다. 닫기 또는 Escape로 돌아오면 카드로 초점이 복원됩니다. 문서 삽입의 컷비율 기본값은 기본입니다. 너비·컷비율·글꼴·글꼴버전은 SDK 호출 옵션이며 YAML 필드로 넣지 않습니다.

영어 문법 호환

v0.3.0 이후 버전은 기존 영어 키와 값도 받습니다. cast/actors/dialogue/transfer와 server/happy/mode: before를 쓴 이전 코드도 유지할 수 있습니다. 같은 객체에 표정과 expression처럼 같은 뜻의 키를 둘 다 쓰면 값이 같아도 오류입니다. ID와 이름표·대사 내용은 번역하지 않으며 한글 ID도 사용할 수 있습니다. null은 표준 YAML 값 그대로 씁니다.

만화그리기/컷그리기/코드블록그리기/렌더러만들기는 각각 renderComic/renderPanels/renderCodeBlocks/createRenderer와 같은 함수입니다. 영어 옵션 width/panelFormat/font/fontVersion과 compact/phone도 호환됩니다. v0.4.0의 만화그리기비동기/컷그리기비동기/코드블록그리기비동기는 renderComicAsync/renderPanelsAsync/renderCodeBlocksAsync와 같습니다. 렌더러 객체에는 renderAsync/renderPanelsAsync도 제공합니다. 다이어그램의 영어 항목은 diagram/type/source/title/height이며 종류는 mermaid입니다. 반환값과 렌더러 객체의 render/renderPanels/clearCache 메서드는 기존 이름을 유지합니다. v0.2.1에서는 영어 문법과 영어 함수만 사용하세요.

사람의 영어 항목은 asset: human, 최상위 personas, 인물의 persona·appearance입니다. 프로필은 role·personality·speechStyle, 외형은 skinColor·hairStyle·hairColor·outfit·outfitColor·glasses를 사용합니다. 머리 값 short/bob/long/bald는 짧은머리/단발/긴머리/민머리, 옷 값 shirt/jacket/hoodie는 셔츠/재킷/후드입니다. LLM 가이드의 영어 호환 표에서 전체 대응을 확인할 수 있습니다.

7. 오류 해결과 현재 한계

  • 없는 캐릭터: 등장인물의 ID와 인물의 ID가 같은지 확인하세요.
  • 화자·상대가 컷에 없음: 화자/상대에 쓴 인물을 같은 컷의 인물에 넣으세요.
  • 알 수 없는 항목: 키 이름의 오타와 대소문자를 확인하세요.
  • 인물 겹침: 가로위치/세로위치를 벌리거나 배율을 줄이세요. 자동 배치로 돌아가도 됩니다.
  • 이름표가 너무 김: 이름표는 두 줄 이내로 줄이세요.
  • 그림이 다르게 보임: SVG에 글꼴을 포함하지 않습니다. 동일한 픽셀 결과가 필요하면 PNG로 저장하세요.

입력은 100,000 문자, 일반 텍스트는 10,000 문자, 다이어그램 원문은 20,000 문자 이내입니다. PNG 배율은 0.5~4, 최대 한 변 16,384픽셀·총 3,200만 픽셀입니다. 자동 경로 회피, 임의 에셋 업로드, 배경 에셋, AI 그림 생성, 계정 저장, CLI는 아직 지원하지 않습니다. 현재 자동 테스트는 Chromium에서 실행합니다.

소품의 받기·버리기·떨어뜨리기·던지기 동작은 별도로 개발 중이며 아직 공개 문법에서 지원하지 않습니다. 현재는 손모양·든소품·전달을 사용하세요.
